# Classroom experience architecture

Sprint 3 starts from main 4c5d48f, the merged Sprint 2 / PR #4. The existing classroom-readiness branch was clean and identical to main after fetching remote references. No repository AGENTS.md instructions were present.

The primary journey is one teacher, one phone, one mirrored projector. Learner assessment remains a separate authenticated workflow; classroom demonstrations must not create learner attempts or attainment records.

TeachingStep is an optional, additive member of the existing immutable LessonDocument revision. Array order defines teaching order. SectionCode maps each step to an existing planning/Ministry section, preserving the original plan rather than replacing it. The phase is bounded text so schools can use different methods. Teacher instructions and notes are distinct from learner-facing explanations, hints and answers. Existing documents deserialize without steps and can be prepared explicitly. Existing saves and accepted AI proposals preserve steps when omitted. Step data is excluded from legacy lesson-generation prompts to avoid introducing private guidance into provider input.

TeachingResource pins ContentItemId, AssetId and SHA-256 checksum, with a readable title. Save validation requires the exact active asset of a currently published resource. Playback must resolve this exact asset and checksum again; a missing or revoked version must be shown as unavailable, never substituted with a newer draft or primary asset. Existing authentication, organisation visibility, ownership, optimistic revision checking, review, audit and media endpoints remain authoritative. No new permissions or database schema are needed: steps are stored in existing revision JSON with document schema version 3.

Initial audit: the Sprint 2 presentation pinned revision but rendered planning section bodies and offered a teacher-notes toggle and global resource selector following the current primary asset. Sprint 3 replaces this behavior in both the new teaching route and the legacy presentation route. Planning prose is mapped only into preparation guidance; learner-facing text is explicit. The server classroom endpoint whitelists public fields and returns no private lesson document or user/school details.

## Implemented flow

`/app/lessons/:id/journey?revision=N` is preparation; `/app/lessons/:id/teach?revision=N` and the compatible `/present` entry point use the public teaching contract. `GET /api/organisations/:org/lessons/:id/classroom?revision=N` requires lesson permission and existing organisation/share/reviewer visibility. Both preparation and teaching pin the same immutable saved snapshot; preparation writes through the existing optimistic-concurrency save transaction. Every subsequent resource access uses the existing published catalogue and media/activity authorization APIs.

The library reuses curriculum relationships to filter lessons server-side by version, grade, subject, term, topic, competency or outcome. It retains recently updated ordering, bounded pagination and historical mappings, rather than searching snapshot JSON or inventing another curriculum model. Preparation supports step/resource order, replacement, safe previews, private guide printing, explicit save and unsaved-navigation protection. Publication rechecks exact approved step assets as well as existing reference constraints.

The teaching canvas uses large responsive type, native touch controls, fullscreen fallback, step navigation, safe overview, explicit answer/hint reveal and a pause/reset timer. Its root covers the administration shell while teaching. Private guidance has no reveal control on that canvas and is absent from the endpoint response. Teachers must stop mirroring before deliberately exiting to private preparation; the application cannot hide device notifications or the preparation screen from an operating-system mirror.

Whole-class playback wraps the fixed declarative activity renderer in a shared self-contained runtime. It disables practice submission, keeps answers/explanations absent until requested, resets demonstrations/questions and adds bounded equal-partition changes for fractions without mutating the published definition. Native controls remain accessible; existing animation pause/restart/reduced-motion behavior is retained. It performs no identity, score, progress or assessment writes.

Schema-2 lesson packages add public teaching steps, exact pinned dependencies and online-equivalent whole-class playback. They exclude private guidance through both server projection and client export whitelists. Downloads preserve the Sprint 2 ranges, checksums, storage limits and final manifest revalidation. The exported fixed-script CSP covers both renderers. File playback verifies bytes, hides non-current resources, pauses media and resets activity reveals when changing steps. Schema-1 exports remain readable; unsupported export versions fail safely. No progress ingestion or identifiable offline storage is enabled.

The existing durable AI queue additionally accepts bounded text plans for visual explanations, worked examples, discussion prompts, activity suggestions and learner explanations. These reuse the storyboard text schema, provider validation, curriculum-only grounding, budgets and provenance. They are review proposals, not runnable animations or automatically published assets. Existing declarative activity proposals still require explicit draft acceptance and independent content approval.

Physical Android/projector acceptance is separate from browser viewport testing. The website cannot promise casting, forced orientation or independent external displays on arbitrary hardware. No native application, production migrations or deployment is authorized by this sprint.

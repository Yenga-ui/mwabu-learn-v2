# Modern login screen — 22 October 2026

The sign-in, account recovery and password-reset screens now share the workspace's restrained visual language: light background, official Mwabu Learn logo, purple typography and primary action, orange accents, subtle borders, consistent controls and compact spacing. No images, fonts, dependencies or UI frameworks were added.

The desktop layout has a compact brand header, a quiet welcome panel with learning/teaching/offline icons, and a sign-in card. Phones show the brand and form directly; the decorative welcome panel is omitted. Guest teacher, guest learner, account request and password recovery links remain visible. Learners are still registered by a parent, teacher or Mwabu; no terms or privacy-policy acceptance is fabricated.

Authentication fields, endpoint calls, cookie/session handling, query-cache clearing, safe return URLs, licence checks and error handling are unchanged. No credentials, account roles, databases or server security settings were modified.

Verification uses the existing five-viewport login test (1366×768, 1280×640, 1024×768, 390×844 and 320×568), real fixture-account sign-ins, logout/refresh tests and a new browser test following guest audiences, registration, recovery and reset entry points. A first layout check found 11px vertical overflow at 1280×640; short-screen spacing was reduced while retaining readable text and 44px controls. No test assertion or viewport was relaxed.

Final results: **96 frontend tests passed**, **15 targeted browser scenarios passed**, TypeScript, strict ESLint and production build passed. Browser coverage includes all five login viewport sizes, all three account-role sign-ins on desktop/phone, invalid credentials, signed-out access, logout/sign-in redirection, single/two-tab session refresh and guest/registration/recovery entry points. No assertions, security checks or timeouts were weakened. The full 70-scenario browser suite was not rerun for this authentication-layout-only change; the targeted scenarios exercise the affected flows.

Screenshots and JUnit results are retained locally under `artifacts/login-ui-2026-10-22/`: `login-1366x768.png`, `login-1280x640.png`, `login-1024x768.png`, `login-390x844.png`, `login-320x568.png`, and `browser-results.xml`. Desktop and phone screenshots were visually reviewed. Tests use isolated fixture accounts, not production credentials. No backend changes or migrations are needed. Existing Vite staging-directory and browser colour-environment notices remain unsuppressed.

The local app remains at `https://localhost:7042`. Refresh the login page to load the new assets after the local frontend is updated. Prior hashed assets are preserved for already-open tabs. No merge or production deployment is performed.
